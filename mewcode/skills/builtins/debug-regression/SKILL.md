---
name: debug-regression
description: 定位程序故障或功能回退，建立最小复现、实施已授权修复并验证回归；仅诊断请求不自动修改代码。
---

先区分用户要诊断还是修复。记录当前项目、变更基线、预期行为、实际行为及可重复的触发条件，保留已有未提交修改。

排查 Agent 功能时先用 AgentStatus（若可用），区分工具不存在、被禁用、模型拒绝调用、运行失败、结果未接收。不要把静态注册或配置里的模型名当成调用成功的证据。

修复流程：

1. 从最小无破坏复现开始；没有稳定复现时记录不确定性，不盲目重启或改配置。
2. 用日志、失败断言和实际调用链定位原因；先检查近期修改与边界，不把症状等同根因。
3. 在授权范围内做最小修复，添加能在旧实现上失败的新测试。测试断言用户可见行为，不能只检查源码字符串。
4. 用 RunVerification 执行针对性回归，再覆盖相邻功能。失败时区分环境阻塞与实现缺陷；不能通过删除断言或更改预期掩盖回归。
5. 对 UI、模型 API、多 Agent 这类链路，增加实际集成验证。Mock 通过只能证明本地逻辑，不能声称外部服务可用。

交付注明根因、修改范围、实际运行的命令与结果、未验证项。审查待完成、子任务仍运行或关键验收失败时不要报完成。
