# 持久化工作项与返修闭环

适用于逐页比对、批量校验等有限清单任务；普通单次咨询不必套用。来自阶段5复核故障的约束，不固定书名、页数、模型或业务路径。

## 设计而不是延长一次聊天

让编排管理阶段依赖与授权，让宿主队列管理每个工作项，让模型判断证据。推荐结构：证据准备 → 实现/候选补证 → 只读审阅与判定；需要返修时回实现，再审阅，全部通过后到汇总/真实用户 gate。

若首轮尚无工作单，实现成员只准备输入；之后通过 ReadReviewQueue 分页读取本循环审查者的未决项，按 item_id、issue_ids 和证据定位返修。明确候选目录、禁止修改的原始来源、产物及验证命令。不要把执行者放在循环外，却要求 reviewer 调用它。

有 RepairWorkBatch 时，不从聊天拼写工作单：先 ReadReviewQueue 取得当前 revision 和 item_ids，再 freeze(expected_revision, item_ids)。一次最多10项，跨页耦合问题放同批；返回稳定 batch_id、逐项裁决版本和原始字节指纹。恢复先从 ReadReviewQueue 的 repair_batches 找批次，再 read(batch_id)，不要按动态 offset 重建旧批次。相同冻结请求幂等；来源变化或他人占用必须先解决，不能跳过检查。

用原有授权工具在候选目录生成独立 candidate、diff、evidence 文件，再 submit(batch_id, candidates)，每项带 issue_ids 及三个文件的字节 sha256。工具只做整批预检和原子登记，不生成业务文件、不赋予写权限、不证明修改正确。失败提交不会部分落账；已提交批次不能覆盖。未提交且不再处理的批次用 release 释放，文件不自动删除。文本审查 sha256 与整文件 file_sha256 不可混用。

启用批次协议后，轮数变化本身不重新派发未改动缺陷；只有新候选或失效证据触发定向复核。审查者从 next 获取候选，实际读取原图、双侧文本及候选，用当前 candidate_revision 提交 record；提交者不能关闭缺陷。汇总只投影宿主台账，不把 submitted/awaiting_review 写成 complete。

并发分两层：宿主协议支持独立批次占用及冲突检查；这不代表运行器已允许返修写入并行。保持现有循环串行规则，不为提速动态改图。需要更多节点时，先提出“只读证据准备 → 授权实现 → 独立复核 → 汇总/用户门禁”的计划修订，说明实际瓶颈与预算。仅工作项、输入依赖和输出路径均独立的批次才有资格进一步设计并行；跨页修正和共享汇总文件保持串行。

用户要求修复缺陷时，设置 requires_repair=true、repair_node_ids。设置并不能授予权限：再核对实现成员工具是否被 deny_tools 禁用、候选输入是否齐全、命令是否获准。用户只要求审查报告时保留只读流程，不擅自加入修复。

## 输入和证据

冻结任务指定的完整清单、稳定键和输入版本，去重并检查数量守恒。初筛清单≠机器意见≠独立审阅≠验收通过，不能混用“完成”计数。

准备节点应提供每项原图、两侧文本、物理页与印刷页/来源索引映射。目录点线、数学小数、符号的规范化必须区分，不能因为正则误报不断增生业务缺陷。校正初筛算法后仍履行已经确认的完整清单，缩范围需用户修订。

审阅者按证据类型选择工具：文本用 ReadFile 或 ReadStageResult，像素用 ReadAuditArtifact 或 InspectVisualEvidence，命令用 RunVerification；criterion_id 绑定 item_id。ReviewWorkQueue(action=evidence, item_id, source_path, source_items_path, source_selector) 返回文本及带通道标签的 evidence_id；整本 JSON 用明确的单页 selector，单页文本可直接读。record 使用 evidence_ids，状态为 pending/pass/needs_repair/unknown（旧 complete 可读），不把 PNG 当 UTF-8，不猜哈希或编造引文。宿主持久化台账不违反业务只读；无 SubmitHandoff 的 reviewer 使用 SubmitLoopDecision。

每项读取、判断、提交后才开始下一批；正常进度不足以完成全队列时接续，不重复已提交项。发现问题登记 needs_repair，证据不足登记 unknown；next 不再次发派本轮这些未决项，先让责任成员补齐。不得把主通道正确、机器 no_discrepancy、用户选择继续当作缺陷已经关闭。

需要像素证据的审阅节点加载 visual-evidence。freeze 的工作项上限不是视觉请求上限：一页的整图、裁图和候选各占图片预算。按项读取并及时落账；安全审查由宿主按真实图片数/字节数完整分包并汇总，不能通过只送最后几张图解决超限。分包不裁剪主对话、不删除历史证据，也不自动启用工具历史剪枝。跨图关联未判清时保持 UNKNOWN，不把分包通过当成业务通过。

## 恢复、迁移和判断边界

普通继续使用同一运行和活动台账。“重跑后续”归档下游进度，不应用作解卡按钮。计划修订或候选变化比较范围/口径/证据；按项验证后迁移，不清空全部台账，也不将原来已审的记录自动升级为新验收。

网络首响应超时、工具输入错误、能力缺失、业务缺陷、等待用户是不同事件。瞬时失败有限重试；坏项隔离，让其他项前进；能力缺失先补图/授权。恢复读取持久化进度，不因超时异常的空返回值而认定没有进展。

安全审核不确定时，只用原权限内只读工具补证，再送审完全相同的原调用；不要改写命令绕过审查。检查点保留待复审调用指纹和次数；重复同一证据、重新连接或“继续”不重置预算。宿主阻止的其他操作不代表审核模型分别拒绝了它们。补证不是授权，候选登记也不属于安全补证；次数耗尽或原调用丢失时明确请求人工处理。

批量闭环用宿主的待处理/完成/缺陷/未知计数判断停滞，不能靠改写总结或重复提交同一裁决无限重置“有进展”。文本证据按页绑定；候选返修后只复核受影响项，连续无进展交有边界的路径诊断或具体人工问题。

主模型提有限路径，Jev或当前选择的审核模型选择。候选必须引用宿主确认的能力与进度；“只读”不等于禁止提交宿主台账。像素证据由具备视觉能力的模型或 InspectVisualEvidence 取得，判定仍由审阅者给出；路径置信度不证明产物正确。不能通过多次询问同一决策绕过预算、授权或人工签认。

## 交付前回归

至少覆盖：部分项提交后断流再续、不重跑前置；无返修能力开跑前拦截；坏项不饿死其余项；缺陷交实现再回审查；同一本 JSON 改另一页不使本页失效；合同变更不能继承旧 PASS；“继续”和“重跑后续”语义不同；未答用户 gate 不放行。

用离线夹具验证状态迁移与调用次数，不用大量付费请求证明恢复功能。最后核对真实图而不仅看 skill 文案；保存与迁移完成后仍保持用户要求的暂停状态。
