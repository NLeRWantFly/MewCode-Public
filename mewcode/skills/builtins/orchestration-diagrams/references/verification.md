# 应用回归与经验更新

仅在修改 MewCode 构图/启动实现或定位应用故障时使用。构建业务图不应自动加入以下开发步骤。

## 验证真实入口

先定位实际请求、日志异常和分支。曾出现 `ModelRef` 漏导入：无 bindings 的启动测试通过，前端实际携带非空角色绑定时失败。回归应提交前端真实形状的确认请求，检查到启动回调，核对已有节点模型及 Effort、完整运行参数契约、后续阶段选择和新建/恢复运行身份。缺少配置时应在产生运行或切换模式之前拒绝。

修复前让回归复现，最小修改后确认通过。配置 Token 预算时，覆盖 UsageEvent 的剩余预算更新及多个接续段；既有输出上限和总预算不因接续重置。定义在其他函数中的局部变量不能供事件处理直接引用。

从当前正式图只读取选定对话的快照，在独立工作区回放并停在启动边界；模拟模型与启动回调，不执行业务工具、不代答后续选择。核对节点、分支、循环、绑定和契约保持。循环控制边可被编译进合同，前向边数与画布边数不同不一定是丢边，应核对转换后的完整关系。

## 统一开发检查

在 MewCode 仓库根运行：

```bash
uv run python scripts/check_startup.py
```

该入口检查后端 F821/F822/F823，并在隔离临时数据根执行启动、预算及打包门禁回归。PyInstaller spec 会在构建前调用；Windows/Linux、Python 3.11/3.14 的 CI 矩阵已配置。直接源码运行仍须先执行此检查，不能宣称所有启动方式都会自动检查。依赖缺失或检查失败应修复后重跑，不能跳过门禁。修改其他功能时另选与变化相关的验收，检查脚本通过不等于全应用无缺陷。

确认运行中的后端确实加载新代码后，才能进行实际界面验证；避免重启其他正在执行的任务。桌面读取失败应保留准确错误，隔离回放不替代真实界面/业务验收。配置存在不证明模型线上可用，也不授权额外付费调用。

## 维护经验

只加入有现场证据、会改变下次判断的规则。区分已验证事实、建议和未验证能力；未启动的真实业务不能作为成功案例。每条新增经验说明问题触发条件和可观察的验证方式，不复制具体项目路径、书名、模型路由、节点数量或历史授权。共用规则在 `execution-readiness.md` 维护，自动构图直接读同一文件；修改后验证实际生成/补全/审查请求获得新内容，且不改变来源、调用额度和输出协议。
