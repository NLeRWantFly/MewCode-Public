# 原生工作流

普通对话首次探索时，主对话负责推进任务。`UpdateWorkflowTasks` 只保存公开执行图，不调用调度器；`intent=execute` 仅为兼容旧参数，表示保存。`items` 支持 `kind/config`，`edges` 表达条件出口，`observations` 记录公开结果、实际子 Agent 标识和循环轮次；阶段性答复不表示任务完成，实际交付后才记录 `completed=true` 和 `summary`。需要子 Agent 时用 `Agent` / `BackgroundTasks` 或显式 `DispatchWorkflowTasks`，不能为了画图派发任务。图的错误、等待、未选路径不限制主对话。

探索中的修改通过主对话表达，不直接编辑或应用图。用户明确提取且任务完成后，才保存图和对话摘要；提取不会执行。只有用户明确复用，才用 `RunSavedWorkflow` 绑定新输入进入按图执行。下文的画布编辑和调度规则适用于明确的流程设计及复用执行。

设计、自由画布与执行器共用 `mewcode.workflow.v2`。Core 只管理依赖、显式控制流和状态持久化；普通执行节点的正常最终回复就是交付，随后推进下游。不要自动添加质量门禁、交付证书、最终模型验收、完美性目标或返修循环。确实需要检查时，按用户需求放置可见的判断节点。

只有四类组件：

- `work`：按任务、输入和约定产出自主完成工作。调查、实现、整理和交付都可以使用执行节点，无需固定套用“规划—实现—审计—汇总”。
- `judge`：产生条件结果。`config.expression` 表示 JSON 条件（如 `{"path":"inputs.ready","equals":true}`）；`config.manual=true` 表示明确需要人工选择；其他判断由该节点绑定的模型完成。
- `branch`：按已有结果路由，不调用另一个模型。`config.source` 指向输入中的值，`cases=[{"equals":"选项值","port":"出口名"}]`，可设置 `default`。连线的 `condition` 对应出口。
- `loop`：包含 `config.graph={nodes,edges,layout}` 嵌套工作流，支持 `mode=foreach/count/until` 与相应 `items/count/until`。循环默认无轮次、时间、Token 上限；只有用户明确要求才配置 `limits`。循环体普通连线仍无环，不画旧式回边。

主图和循环体均按真实依赖调度：无依赖的节点可并行，有多个上游的节点等待其实际需要的输入。未选择的条件路径不阻塞汇合，失败只影响依赖它的下游。无需额外添加汇总节点；用户要求统一交付时再配置。

用 `ReadWorkflowBlocks` 读取当前版本、节点和来源。用 `SubmitWorkflowBlocks` 保存节点、连接及要求；节点的 `data.node_kind` 使用上述四类，`data.config` 保存组件参数，模型填写实际 `provider_key/model_id/effort`。嵌套图节点使用 `id/kind/label/task/config/inputs/outputs/model`，连线使用 `id/source/target/port`。保持原节点 ID 与模型配置；仅在任务明确需要时增加组件。工具服务与节点模型是不同的配置，不据模型列表猜测 OCR 等服务是否可用。

本轮已明确的节点直接保存，再调查必要的未知条件。环境准备可以放在执行节点前部或依赖节点中；代表样本和验证按任务实际需要安排，不强制增加独立验收轮。只有用户独有的信息或真实业务取舍才询问；现有工具权限由 Agent 处理，不预置重复授权门禁。

规格完成后用最新 revision、sequence 和来源哈希调用 `AdvanceTaskDesign(action="build")`。宿主直接编译已保存的节点、校验引用和拓扑并保存，不再重新抽图或调用模型评审。设计意图为“只生成图”时保存即结束；允许执行时才启动业务。

单个工具报错、超时或结果未知由节点自行修正、检查实际状态或选择可行方法。保留成果与原始错误，从未完成部分继续。可能已生效的外部操作先核对再接续，不盲目重放。模型对话结束而未交付时显示阻塞；无输出时长不用于判断结束。

运行中可以改图、暂停、继续、局部重跑或采用历史交付；节点之间通过追问和补交解决缺漏。需要复用时提取完整结构和公开对话摘要。来源摘要不是授权，旧结果不是新任务已经执行的证据。
