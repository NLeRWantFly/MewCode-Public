# 读图与取证

先明确本次需要从图中回答的问题、来源文件/页面和关联工作项。使用当前已授权的图像工具；有 ReadAuditArtifact 时，PDF 使用 render_page=true。工具缺失时先发现能力，不把 skill 的存在当成视觉能力或工具授权。

先读能提供定位上下文的整页/截图；细小符号、数字或连线仍不清楚时，针对具体问题读取局部区域。crop 使用源图的 x,y,w,h 像素坐标，不沿用显示缩放后的坐标。根据工具返回的尺寸修正越界裁图，不盲目重试同一区域；保留裁图到原页的映射，不把放大、增强或 OCR 当成原始证据。

每项记录 source/page、criterion_id 或 item_id、原图/像素指纹、crop、实际观察、结论和仍不确定的部分；工作流提供 evidence_id 时优先引用宿主 ID。业务正确性需要跨图比较时，明确关联图及比较问题，不能用几个孤立的局部结论拼出 PASS。

## 长任务与图像容量

以独立工作项组织“读取 → 判断 → 记录”，关联页同组处理；完成一项就提交台账，不把整批全部图片读完后才记录。一个工作项可能含整页、多个裁图和双侧候选，工作项数量不是图片数量。

安全审查由宿主对实际图片数及序列化大小预检，完整分包后汇总；skill 不得承诺固定页数一定能装下，也不得把每包 allow 或“像素已交付”当成工具授权/业务验收。判定由审阅者给出；审阅者不支持图片时用 InspectVisualEvidence 取得观察，不能把观察当作授权或验收。

复用仍有效的观察和证据引用，不重复读取相同像素+问题+区域来制造进度。恢复时先读取当前工作项、候选版本及已完成记录；原图、候选或判定问题变化才重新确定所需证据。历史图片和审查记录不因分包而删除，工具历史 shadow 仍只提供建议。

遇到容量/坏图错误，查看实际图片数、字节数及越界信息；将单张过大的证据拆为可追溯区域，或按独立工作项组织输入。不得丢掉必要证据、降级成文字审查、改写原调用绕过审查，或修改权限/验收解卡。普通“继续”仅在宿主重新核验输入后接续，不能代替审查通过。

不能确定时记录 UNKNOWN/PARTIAL 和具体缺失证据，不猜测。只有确需新的用户信息、授权或无法恢复的证据时再提出具体问题，不把本地图像超限统称为服务不可用。
