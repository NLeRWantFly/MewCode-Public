---
name: multi-agent-delivery
description: 在用户要求多 Agent 协作或任务确需独立执行与审查时，划分任务、约束并发写入、接收结果并完成主 Agent 验收。
---

先检查项目 AGENTS.md、AgentStatus 和可用模型配置。遵守项目指定的执行路由，不因外部 worker 失败而擅自换模型。工具不可用时报告具体缺口；不要用文字声称已经派发。

每个子任务必须声明输入范围、允许修改的文件、禁止修改的内容、交付物和验证命令。主 Agent 保留需求判断、架构、权限风险与最终验收。只有独立且有收益的子任务才并发；同一文件的写入串行化，或使用显式隔离的 worktree。

派发时记录任务 ID、子模型、职责与依赖。主 Agent 继续不依赖该结果的工作；如果结果阻塞交付，使用 BackgroundTasks 有界等待，不循环刷状态、不在子任务仍运行时宣称完成。

失败或重启后：

- 先读取任务结果与部分改动，确认是否留下未完成操作。
- TaskRetry 是从保存的请求重新执行，不是原位 checkpoint 恢复。只有确认重复执行安全后才设置 side_effects_checked。
- 不自动重放付款、发布、删除或其他不可幂等操作；fork/team/worktree 等不支持的任务应重新明确范围。
- 保留旧任务记录及 retry_task_id，防止重复提交。

收到结果后核对实际文件和命令证据。独立审查应针对最终改动，报告 PASS/FAIL/PARTIAL 与具体证据。主 Agent 解决冲突、重跑必要验收，再向用户交付；不能把子 Agent 的自评当成最终验收。
