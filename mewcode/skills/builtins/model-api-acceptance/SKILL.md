---
name: model-api-acceptance
description: 接入或修改模型供应商、API 协议、effort 与子 Agent 路由时，验证模型能力和实际端到端调用，区分配置成功与服务可用。
---

记录目标供应商、base URL、实际模型 ID、协议与用户要求的能力。不要从展示名称猜模型 ID，也不要把路由标签当模型 ID。读取凭据只用于已授权调用，不输出密钥、请求认证头或完整敏感日志。

按实际需求验证：

1. 最小文本请求与流式请求，确认首 token、正常结束、错误传播和取消。
2. 工具调用：使用无副作用的本地假工具，检查参数、调用 ID、结果回传以及下一轮回答；工具描述出现在请求里不等于调用链成功。
3. effort：只发送该路由支持的字段和值。观察实际请求映射；不把 API 接受字段等同于模型确实支持推理档位。
4. 子 Agent：检查父子供应商/模型/effort 的继承与显式覆盖。审核模型与执行模型分别验证，不混为同一设置。
5. 限流、超时、认证失败、未知模型、流中断：保留可定位错误，不静默降级成别的模型、不无限重试。

先做无网络单元测试；真实探测限制次数和 token，并且只访问用户指定的服务。若调用收费或会发送敏感内容，按任务已有授权边界处理。服务不可访问时报告阻塞，不能用 Mock 结果冒充线上验证。

交付一份能力矩阵：已实测 / 仅配置验证 / 不支持 / 未验证，附脱敏的错误信息和验证方式。
