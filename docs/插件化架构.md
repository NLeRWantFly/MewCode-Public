# MewCode 插件化架构

MewCode 的插件边界参考 DeepSeek Harness 的 Cordis Host/Client 分离思路，
但 Host 侧仍使用 Python 原生 API，避免把 DSH 的 TypeScript 运行时代码硬搬到
TUI/Web 后端。

## 插件目录

项目插件放在：

```text
.mewcode/plugins/<plugin-name>/
  plugin.toml       # 可选
  plugin.py         # 可选，导出 PLUGIN
  skills/           # 可选，包含 Skill.md 或目录型 Skill
  agents/           # 可选，包含 Agent markdown
```

用户级插件放在 `~/.mewcode/plugins/`。同名插件由项目级插件覆盖用户级插件。
一个只有 `skills/` 或 `agents/` 的目录也能直接加载，不需要写 Python。

`plugin.toml` 示例：

```toml
[plugin]
name = "my-tools"
version = "1.0"
purpose = "Project-specific coding tools"
entry = "plugin.py"
requires = ["core.runtime"]
inject = ["llm"]
```

## Python 插件

插件文件导出 `PLUGIN`，可以贡献服务、工具、命令或 UI/API 槽位：

```python
from mewcode.cordis import PluginSpec


def apply(ctx):
    ctx.slots.register(
        "core.tools",
        MyTool(),
        item_key="MyTool",
    )


PLUGIN = PluginSpec(
    "my-tools",
    apply,
    requires=("core.runtime",),
    inject=("llm",),
    version="1",
)
```

宿主提供四类槽位：

- `single`：唯一实现，例如根 UI 容器。
- `list`：可叠加贡献，例如 API、Skill 来源。
- `keyed`：按稳定 ID 组合，例如工具和命令。
- `chain`：按优先级和 selector 选择实现，例如渲染器。

插件在 `apply` 中注册的所有 effect、事件监听、服务和槽位都会归属于该次
运行实例。加载失败会回滚已注册内容；卸载会先停止依赖插件，再逆序清理自身
effect。`Context.inspect_plugins()` 和 Web 的 `GET /api/plugins` 可查看状态、
版本、运行实例、等待中的服务和槽位占用。

## 迁移规则

核心功能通过 `ApplicationHost` 组合：`core.runtime`、`core.tools`、
`core.commands`、`core.catalogs`、`core.hooks`。TUI、headless prompt 和
WebSession 都从自己的 Context 获取 Registry/Loader；旧的 `ToolRegistry`、
`CommandRegistry`、`SkillLoader`、`AgentLoader` API 保留作为兼容面。

浏览器端使用 `frontend/static/plugin-runtime.js` 提供同名的 UI Slot 思路，
对话和轨迹是两个可替换的 keyed contribution，并通过事件通知视图切换。
