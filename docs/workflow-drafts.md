# 流程底稿与流程图生成

入口为当前对话“编排 → 流程底稿与生成”，配置面板的生成按钮也转入同一个核对入口。

## 用户工作流

1. 点击“整理新增记录”。首次从原始会话 JSONL 开始，包括压缩前的用户和公开助手消息、与问题配对的人工回复；不读内部思考、一般工具输出或附件正文。
2. 每块成功即保存来源游标与候选底稿。失败、停止或重启后可继续；不会重复处理已经成功的块。
3. 核对条目、修改前内容、来源引文和未采用原因。人工编辑能修正名称、正文、状态和高级结构，冲突可保留旧条款或明确采用新条款。
4. 确认底稿版本后生成流程图差异。生成是确定性投影，不再调用模型重写整张图。新增/修改/删除节点、依赖、目标约束和循环单独列出。
5. 用户再次确认差异，保存为当前对话的画布与计划版本；不启动执行。运行中的对话或编排不会被替换。已打开的旧画布须重开；其过期保存会被版本检查拒绝。

通用模板见 [workflow-draft.md](templates/workflow-draft.md)。论文案例产物位于本地 output/，不包含在产品模板里。

## 数据边界

- 持久化位置：项目 .mewcode/workflow-drafts.sqlite3，按 (conversation_id, draft_id) 隔离。当前 UI 使用 main，API 支持独立 draft_id。
- 原文来源有稳定 ID、物理行号、时间和分片编号；模型的每项变更必须附实际来源和逐字引文。
- 模型对用户原话的归纳依然待用户核对，不自动赋予“作者确认”状态。助手消息不能静默替换已有用户/画布要求，会进入冲突。
- 模型只能 upsert 或显式 retired；省略条目不是删除。旧状态保存在已确认版本中。恢复旧版本创建新版本，不删除历史，也不自动改图。
- 原始历史变化、损坏、缺失或不完整行会明确提示。确认时刷新来源；有新增未处理片段或读取缺口不能伪称已完整整理。
- 循环及前向依赖经过现有编排校验。层级 parent_id 保留在元数据中作为分类关系，不自动变成执行依赖。
- 保留已有节点的模型、工具、位置和恢复策略；不复制运行状态。流程要求与历史进度分别保存。
- 节点专属约束接入节点执行要求，不扩大为全局规则。人工备注与附件保留；撤回底稿约束只移除该底稿拥有的要求。
- 当前源同步在打开面板、轮询或用户整理/确认时进行。原始消息本身已随对话持久化；没有每轮静默模型调用，也没有隐藏的收费后台总结。
- 整理期间画布发生变化时，新的画布基线自动并入当前候选底稿（新增基线条目、更新基线指纹），不再要求丢弃进度做全量重扫。
- 切换对话或关闭底稿面板不会中断后台分块整理；重新打开面板可继续查看进度与结果。

## API

### 自动构图与结构修复

自动构图使用 30 分钟活跃请求时间的软提醒。正在响应的模型请求不因总时长或固定调用次数被打断；在结果校验和保存后，由构图模型根据成果、剩余问题和被拒绝的修法决定继续或收束。连接异常、输出截断及手动停止仍分别处理。

“修复当前图”和“让 AI 继续完善”会保存独立的修复草案，持续核对整图的连线、循环调度、计划交接和独立审核路径。未通过校验的提案不进入最终采用窗口；通过后才展示差异，用户明确采用后写入候选图。业务取舍仍使用待决事项，原有职责、验收、锁定条目及已有循环预算保持受保护。

阶段导航显示当前工作、最近保存的成果和下一步。历史片段覆盖率只表示阅读进度；流事件和推理字数放在请求详情。技术诊断默认折叠，模型收束、请求失败和等待采用分别展示。停止或关闭窗口后可从已保存的草案继续。

构图状态及 `/progress` 响应增加 `process`（阶段、成果、后续步骤、软提醒及相关节点）；公开状态不包含内部修复草案。`repair` 的 `local` 操作可携带当前 `preview_id` 继续完善旧修订。草案持久化不改变候选图的版本，最终采用仍检查候选版本、来源与画布基线。

### 兼容底稿接口

- GET /api/orchestration/draft：同步原始来源、版本、候选、覆盖计数和变更。来源按文件大小与修改时间缓存，元数据未变化时不重读原始 JSONL。
- GET /api/orchestration/draft/progress：整理中的实时进度（当前块、模型阶段、已用时间、每块日志）；只读内存进度与 sqlite 状态，不重读原始历史。
- POST /api/orchestration/draft/update：开始/继续分块整理；rebuild:true 显式重新扫描。
- POST /api/orchestration/draft/action：stop / edit / confirm / restore。
- GET /api/orchestration/draft/source/{id}：当前底稿所属的公开来源。
- GET /api/orchestration/draft/export：Markdown。
- POST /api/orchestration/draft/graph：preview / apply；apply 只接受服务端保存的 preview_id。

所有请求都携带 project、conversation_id，作用域必须与活动对话相同。模型 route/effort 在整理开始时冻结；tools=None。每次模型返回后校验作用域、底稿序号、源游标及画布基线，迟到响应不能覆盖其他对话或新版本。

## 上限与非目标

- 原始文件安全上限 100 MiB；单片 6000 字符，块约 18000 字符；当前模型输入合计上限 160000 字符，超过时提示而不截尾。
- 旧单次抽取入口超过 16000 字符会明确要求转入底稿，不再丢弃前文。
- 来源覆盖率不是模型理解准确率；引文存在也不证明归纳完全正确，仍需人工核对。
- 不扫描无关项目、不重新授权历史执行、不自动读取附件正文、不把已有成果自动验收。
- 不在本功能中自动执行或重跑论文/其他业务任务。部署新后端应等待当前任务方便停止或结束。
